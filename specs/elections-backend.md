# Desired user behavior

The future Elections feed shows people candidates for their House district and Senate races, with concise policy positions grounded in campaign websites. FEC registration is not proof of ballot access; do not present this as a definitive ballot. Loading, no available positions, and failed processing must be distinguishable. Source links and retrieval dates accompany positions.

- [x] Implement AI-assisted website discovery using each matched FEC candidate's name, office, state, district when applicable, and election year. OpenAI web search returns a likely candidate-site URL and retains its search sources as provenance; a source URL does not need to share the campaign site's domain. Page discovery reads `robots.txt`, follows a bounded number of sitemap indexes, and prioritizes relevant pages listed on the proposed site or its `www` alias. If no relevant sitemap pages are available, OpenAI web search is restricted to the proposed campaign domain and uses a site-qualified query with common policy-page titles and paths (including Key Issues and `/key-issues`) to find detail-page URLs. The server fetches only bounded pages on the proposed site or its `www` alias; it does not fetch the homepage or use navigation links as fallbacks. Sitemap and search-result titles/paths prioritize policy, issues, campaign promises, platform, and candidate/race pages. AI page inspection can mark a site `verified` when it supports the candidate and exact race, `ambiguous` when a likely campaign site was found but the pages don't fully state the race, or `rejected` when they conflict. An ambiguous page-inspection result is eligible only when discovery returned a valid campaign URL, approved same-site origins, and a current seven-day review window. Ambiguous search results without a validated URL remain ineligible. Missing sites and proposed records caused by fetch/search failures remain out. No separate corroborating source or manual review step is required. Run discovery explicitly with `node server/src/elections/cli.js --discover-sites --write --states WY --offices house`; defaults limit each run to 20 candidates and five pages per site. The command writes to the configured `DATABASE_URL`. Previous bounded live results are documented in [campaign-site search coverage](elections-campaign-site-search-coverage.json).

## 2. Crawl matched campaign sites with Crawlee

The crawler first uses sitemap URLs that indicate policy, issue, promise, platform, or related campaign-content pages. If none are listed, it uses domain-restricted web search to find relevant page URLs. It fetches only bounded URLs on approved campaign-site origins; it does not start at the homepage or expand HTML navigation links. Current `verified` and `ambiguous` sites with a URL, approved origins, and an active review window can be crawled. Sites without matching pages produce no crawl pages, so they contribute no positions. Extracted positions retain the existing allowed-topic and exact-source-excerpt checks before publication.
